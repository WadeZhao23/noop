# 9点23 — Apple Watch edition

This fork targets iPhone + Apple Watch. The upstream project is [ryanbr/noop](https://github.com/ryanbr/noop), under the existing PolyForm Noncommercial license. Internal targets, bundle IDs, App Group, database location and keychain identifiers remain unchanged.

## Data contract

`AppleHealthAdapter` reads HealthKit into dated `AppleHealthDay` envelopes. Each retained sample includes its UUID, writer, device-source identity, time interval and value. `WhoopStore.replaceAppleHealthWindow` replaces the imported window, daily aggregates, metric series, sleep sessions and workouts in one SQLite transaction. A failed query never calls this replacement. A failed transaction rolls back. Observer anchors advance only after every affected window commits. Deleted UUIDs resolve to their cached dates, including historical sleep wake days.

The first sync reads 30 calendar days. Selecting a historical day and refreshing reads the preceding 30-day window. Observers reconcile the retained history, and query sleep with an expanded boundary so the first night is not clipped at midnight. Apple mode requests read scopes only and bypasses the legacy import write-back path. An explicitly started Watch workout remains a separately authorized user action.

Sleep normalization prefers a Watch writer, chooses a complete session from a single writer, reports competing writers, and deduplicates overlapping intervals. It reuses the upstream night bridging/main-night selector. A complete session belongs to its wake day; naps are listed separately. Unspecified sleep counts as asleep without becoming core sleep. Uncovered/conflicting intervals remain unknown and prevent a Rest score. A missing stage is never imputed as zero in the detail UI.

Quantities use HealthKit daily statistics, including its cumulative source reconciliation for steps and energy. SDNN, resting HR, respiration, SpO2 and sleeping wrist temperature use daily averages. Raw sample values remain available for reconciliation. Values are calculated at full precision; ordinary values display one decimal, scores/steps whole numbers, and sleep duration whole minutes. The detail page identifies the date, timezone, cutoff, actual writers, update timestamp, sample UUIDs and algorithm version. Workout duration is not Apple's exercise-ring minutes.

## Model and presentation

`Nine23Metrics` resolves the same `AppleMetricEngine` result for today, trends, details, the widget and Watch transport. Routes contain the metric, Apple source and selected date; none substitutes the newest available day. Missing data, baseline building, simplified estimates and stale data have separate states. Historical records keep their original timezone and query cutoff.

Recovery retains `WatchRecovery → RecoveryScorer` weights and mapping. It uses daily SDNN, rounded Apple resting HR, and the original personal baseline machinery. Dated history inserts missing calendar days, excludes the scoring day/future dates, and applies both recalibration epochs. Seven accepted prior days are required for a score; 14 accepted days determine baseline maturity. Missing SDNN produces no score. Missing/insufficient resting-HR baseline uses the existing HRV-only fallback and is marked simplified. Scores and explanations come from the same computation. These are repository model rules, not medical validation or official WHOOP equivalence.

Rest retains the upstream formula, an eight-hour target and its neutral consistency fallback. It runs only for one complete main sleep with measured stages and a determined interval/efficiency. Respiration, SpO2 and wrist temperature remain independent measurements. Activity displays recorded workouts, duration, HR, energy and the most relevant associated HealthKit effort sample when available. There is no composite strain/load score in the Apple homepage.

The expanded reference UI uses 首页 / 健康 / 社区 / 更多. The homepage retains sleep, recovery and activity, then adds the daily timeline, journal, sleep plan and customizable metric dashboard. Dated details expose sleep stages, recovery factors, workout records, trends and provenance. Advanced settings stay under 更多. App/Watch/widget branding uses 9点23 and the reproducible black/white `9:23` wordmark generated by `Scripts/generate-nine23-icon.swift`. See [NINE23_REFERENCE_UI.md](NINE23_REFERENCE_UI.md) for the full screen map and public WHOOP references.

## Compatibility boundary

Migration `v48-apple-health-day` adds an Apple-only local cache. It does not alter existing table columns or the `.noopbak` wire whitelist. Both copies of the schema oracle explicitly record this divergence. No Android algorithm/UI adaptation is included in this edition; original array-based recovery callers keep their formula. Shared macOS code is built and tested.

## HealthKit references

- [Sleep category semantics](https://developer.apple.com/documentation/healthkit/hkcategoryvaluesleepanalysis): in-bed envelopes overlap stage samples; unspecified sleep is distinct from core.
- [Workout effort relationships](https://developer.apple.com/documentation/healthkit/hkworkouteffortrelationshipquery): effort is retrieved through the workout relationship, not inferred from a default or converted from strain.

HealthKit intentionally does not reveal whether an empty read means permission was denied or no data exists. Empty states therefore say no readable samples, without claiming permission status from sample absence. Exact parity with the Health app requires matching its date, timezone, data source and cutoff; the app exposes those inputs for device reconciliation.
